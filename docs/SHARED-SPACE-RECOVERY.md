# استعادة عضوية المساحة المشتركة

17 نوفمبر 2026

## السبب والإصلاح

كان `backupData()` يستبعد العضوية، وكانت `applyBackup()` تستدعي `spDetach()`، فتفصل العضو وتزيل النسخ المحلية لسجلات الآخرين. كذلك كان اختلاف UID بين Firebase والحالة المحلية يؤدي إلى خروج محلي تلقائي. لم نجد مسحًا متعمدًا لبيانات WebView في مسار تثبيت التحديث؛ لا يمكن نسبة كل حالات التحديث لهذا السبب دون تجربة APK على الجهاز المتأثر.

النسخ الجديدة تحتفظ بـ `space` وإعدادات المشاركة وملكية المصروفات، وبـ `spaceRecovery` لهوية Firebase الحالية. الاستعادة توقف المزامنة مؤقتًا، وتعيد التشغيل بعد مهلة التراجع (8.5 ثانية) لتقرأ Firebase نفس الهوية قبل فتح المستمعين. استعادة نسخة قديمة لا تفصل عضوية موجودة على الجهاز. عند فقد الهوية أو اختلافها، تظل العضوية والبيانات محفوظة ويظهر احتياج استعادة الهوية، دون إنشاء عضو بديل تلقائيًا أو مسح العضوية.

## الاستخدام

1. ثبّت هذه النسخة كتحديث بنفس توقيع التطبيق، وافتح المساحة المشتركة واتصل بالإنترنت.
2. أنشئ **نسخة احتياطية جديدة** إلى ملف أو Drive. النسخ السابقة لا تحتوي معلومات الدخول المفقودة.
3. بعد إعادة التثبيت، استعد النسخة وانتظر انتهاء مهلة التراجع وإعادة فتح التطبيق. يتصل التطبيق بنفس UID والمساحة إذا كانت بيانات الدخول صالحة والعضوية ما زالت موجودة.
4. تظل صلاحيات صاحب المساحة فعالة: النسخة لا تعيد عضوًا أزاله المالك، ولا تفتح مساحة مغلقة، ولا تتجاوز إلغاء هوية الدخول من Firebase.

إذا كانت النسخة قديمة والجهاز الأصلي غير متاح، لا يمكن استنتاج هوية الدخول من الاسم أو كود المساحة. يلزم طلب انضمام لنفس المساحة وموافقة المالك؛ إنشاء مساحة جديدة ليس مطلوبًا.

## حماية النسخة وحدود التنفيذ

هوية الاستعادة تتضمن بيانات اعتماد Firebase؛ من يحمل نسخة غير مشفرة قد يستطيع الدخول بنفس الهوية ما دامت صالحة. يوجد تنبيه بذلك بجانب إعدادات النسخ، والتشفير بكلمة مرور متاح. لا تشارك النسخة، ولا تضعها في GitHub أو ضمن بلاغ. لا تُدرج بيانات الاعتماد في مستندات المساحة أو التقارير أو سجل الأخطاء.

يستخدم محول الاستعادة تنسيق `browserLocalPersistence` الخاص بإصدار Firebase المضمّن، مع `User.toJSON()` وفحص المشروع وUID وحدود الحقول. لا يُعدّل bundle Firebase. يجب إعادة اختبار المحول عند ترقية المكتبة؛ تنسيق التخزين الداخلي ليس API ثابتًا. تمت تجربة القراءة بمكتبة Firebase الحقيقية المضمّنة، مع ردود خادم محاكاة وحظر الاتصال بالإنتاج. فحص UID محليًا لا يمنح صلاحية؛ الخادم يظل مسؤولًا عن صحة الرموز وقواعد العضوية.

هذا إصلاح للمساحة الموجودة، وليس تنفيذًا للمزامنة الكاملة أو الحساب المالي المشترك المقترحين في البنود 13–15. الهوية المجهولة ليست بديلًا دائمًا عن تسجيل دخول مرتبط بحساب؛ حذفها أو إلغاء رموزها على الخادم قد يمنع الاستعادة. تحويلها لحساب دائم تطوير مستقل لاحقًا.

مراجع: [Firebase anonymous authentication](https://firebase.google.com/docs/auth/web/anonymous-auth)، [Firebase User API](https://firebase.google.com/docs/reference/js/auth.user).
