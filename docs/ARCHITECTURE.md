# معمارية مليم — دليل المطوّر

## الفكرة
تطبيق أندرويد واجهته صفحة ويب واحدة (HTML + CSS + JavaScript) داخل WebView، وجسر Kotlin اسمه `AndroidBridge` للأشياء التي تحتاج أندرويد (الملفات، الصوت، التذكيرات، الويدجت، قراءة الإشعارات، Drive، التحديث). البيانات في `localStorage` (المفتاح `maleem.v1`) والإيصالات في IndexedDB. لا يوجد خادم خاص بنا؛ المشاركة العائلية عبر Firebase Firestore (اختيارية).

## شكل المستودع
| المكان | الغرض |
|---|---|
| `src-web/` | **مصدر الواجهة، وهو ما تعدّله.** `index.template.html` (الـ HTML)، `css/*.css`، `js/*.js` |
| `app/src/main/assets/www/index.html` | ناتج التجميع، **وهو ما يُشحن في التطبيق**. لا تعدّله يدويًا |
| `i18n-src/` | **مصدر الترجمة**: `tr/*.txt` (سطر لكل ترجمة) و`en.base.js` / `ar.base.js` (الجزء اليدوي) |
| `app/src/main/assets/www/locales/` | ناتج الترجمة: `ar.js` (فصحى) و`en.js` (إنجليزي) يُبنيان من `i18n-src/`، و`eg.js` (المصري، بلا ترجمة) |
| `app/src/main/java/com/heshamtaha/maleem/` | Kotlin: `MainActivity` (الجسر)، `PayParser` و`PayCapture` (الإشعارات)، `DriveBackup`، `Reminders`، `Widgets`، `Rates`، `Updater`، `Feedback` |
| `tests/` | اختبارات المتصفح (Playwright) واختبار Kotlin الأصلي |
| `tools/` | `build-www.cjs` (تجميع الواجهة) و`build-locales.cjs` (تجميع الترجمة) و`code-map.cjs` (خريطة الكود) |
| `docs/` | هذا الملف و`CODE-MAP.md` (يتولّد) و`RELEASING.md` |
| `update.json` / `rates.json` | يحدّثهما الـ workflow؛ لا تعدّل `latest` يدويًا (الحقل `message` وحده يدوي) |

## سير العمل عند أي تعديل في الواجهة
```sh
# 1) عدّل ملفات src-web/ (انظر docs/CODE-MAP.md لمعرفة أين كل شيء)
node tools/build-www.cjs        # 2) يبني index.html
node tools/code-map.cjs         # 3) يحدّث خريطة الكود إن أضفت دوال
node tools/build-locales.cjs    # 3ب) إن غيّرت i18n-src/ (الترجمة)
npm install --prefix tests --ignore-scripts      # مرة واحدة
npm test --prefix tests         # 4) كل الاختبارات: lint + تغطية الترجمة + المتصفح
# 5) ارفع src-web/ و index.html (وخريطة الكود) معًا
```
الـ CI يفشل إن لم يتطابق `index.html` مع ما تبنيه `src-web/` (`node tools/build-www.cjs --check`).

**قواعد التجميع**
- ملفات `js/` تُلصق بترتيب الاسم داخل **دالة واحدة** (`(function(){ 'use strict'; … })();` في القالب). كل الملفات تتشارك نفس النطاق، لذلك لا يوجد `import`؛ الترتيب هو ترتيب التحميل. أي `const` يُستخدم وقت التحميل لازم يكون في ملف أسبق.
- ملفات `css/` تُلصق بترتيب الاسم، والترتيب هو الـ cascade.
- كل الملفات بنهايات أسطر Windows (CRLF) وتنتهي بسطر جديد؛ الأداة ترفض غير ذلك.
- لإضافة ملف جديد: سمّه برقم يحدد مكانه (`045-…js`) وأضف وصفه في `tools/code-map.cjs`.

## الحالة والبيانات
- `S` هو الكائن الوحيد للحالة. `save()` يحفظه، وكل دوال `clean…` (في `010-state-and-storage.js` وما بعده) تنظّف ما يُقرأ من الجهاز أو من نسخة احتياطية.
- **إضافة حقل جديد لسجل:** (1) أضفه في دالة `clean…` الخاصة بالسجل، (2) تأكد أنه يمر في `backupData` / `applyBackup` (`090-…`)، (3) إن كان السجل يُشارك فراجع `150-shared-space.js`، (4) أضف اختبارًا يعيد التحميل والنسخ والاستعادة. تعديل الواجهة وحدها يفقد البيانات عند إعادة التحميل.
- التكرار الشهري/الأسبوعي/اليومي: `fixedOccurrences` (في `130-…`) مصدر الحساب الوحيد للتوقعات والمواعيد والتذكيرات.
- السلف: عملة مستقلة لكل سلفة (`cur`)، و`accAmt` مبلغ الحساب التاريخي ولا يُستبدل بسعر اليوم.
- العملات الخام المختلفة لا تُجمع.

## النوافذ (Sheets)
كل نافذة سفلية تُفتح بـ `openSheetEl(id)` وتُغلق بـ `closeSheets()`. **أي نافذة جديدة يجب أن تُضاف إلى القائمة داخل `closeSheets`** (في `050-expense-form.js`) وإلا لن تُغلق مع الباقي.

## الترجمة
- النص الأصلي في الكود بالمصري. كل نص يصل الشاشة يمر على `trText` (في `010-…`) فيُترجم تلقائيًا إن كانت اللغة ليست المصري: (1) تطابق كامل في `x`، (2) تقسيم على « · » وترجمة كل جزء، (3) قواعد `p` (regex، الأدق أولًا)، (4) استبدال رمز العملة العربي عبر `sym` (إنجليزي فقط).
- **أي نص عربي جديد يجب أن يُترجم** إلى الإنجليزي وإلى الفصحى (ما فيه عامية فقط). النص يُترجم كاملًا لا جزؤه؛ والجملة التي فيها « · » تُترجم كل قطعة منها وحدها. نصوص المستخدم (أسماء الحسابات والأعضاء والفئات المعدّلة) لا تُترجم.
- **كيف تضيف ترجمة:** أضف سطرًا في `i18n-src/tr/en-*.txt` (أو `ar-*.txt`) بصيغة `النص المصري => الترجمة`. استخدم `§` لأي جزء متغير و`№` لرقم، وفي الترجمة `§` و`№` يأخذان المتغيرات بالترتيب (أو `$1 $2` لاختيار واحد)، و`re:<regex> => الترجمة` لتعبير نمطي خام. ثم `node tools/build-locales.cjs` يبني `locales/en.js` و`ar.js` (الجزء المكتوب يدويًا في `i18n-src/en.base.js` و`ar.base.js`؛ والمدخلات الموجودة فيه لا تُستبدل). **لا تعدّل `locales/*.js` يدويًا**؛ الـ CI يفشل إن لم تتطابق مع المصادر.
- `tests/i18n-coverage.cjs` يفشل عند ظهور رسالة عربية جديدة بلا ترجمة؛ ما لا يُترجم عمدًا (كلمات البحث بالصوت، أجزاء جمل) مسجّل في `tests/i18n-baseline.json`. بعد الإضافة: `node tests/i18n-coverage.cjs --update` إن كان النص غير واجهة.

## الجسر والأمان
- كل دوال `@JavascriptInterface` في `MainActivity.kt` تبدأ بفحص `pageOk` (الصفحة المحلية فقط). أي دالة جديدة تفعل الشيء نفسه.
- `MainActivity` يحسب سياسة CSP من بصمات السكربتات الداخلية وقت التشغيل؛ لا حاجة لتحديث بصمة يدويًا، لكن لا تضف سكربتًا خارجيًا من مصدر غير موثّق.
- الروابط الخارجية تُفتح لـ http / https / mailto فقط.
- `Updater.kt` يرفض ملف تحديث بلا `sha256` أو بتوقيع مختلف.

## الاختبارات
`npm test --prefix tests` يشغّل بالترتيب: كل مجموعات المتصفح، ثم `i18n-coverage` ثم `lint`. اختبار Kotlin (`NativeRegression.kt`) يُجمَّع في CI (`native-parser`). كل مجموعة ملف `.cjs` مستقل يحمّل `index.html` من القرص بمتصفح Chromium ويكشف الدوال التي يحتاجها (انظر رأس أي ملف). `tests/lint.cjs` يفحص الأسماء غير المعرّفة والمتغيرات غير المستخدمة وغيرها.

## ما لا تغيّره بدون سبب
- ترتيب ملفات `src-web/` (هو ترتيب التنفيذ).
- نهايات الأسطر CRLF.
- مفتاح التخزين `maleem.v1` وأسماء حقول البيانات (تكسر النسخ القديمة).
- قرارات المنتج الموثّقة في `MALEEM-AI-HANDOFF.md` (قسم «القرارات المحفوظة»).
